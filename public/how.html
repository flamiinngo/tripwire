How it works

A second machine for code you don't trust yet.

From the moment you paste a link to the verdict, here is everything Tripwire does, and which CreateOS capability makes each step possible.

01Isolate

Every repo gets its own machine.

Tripwire creates a fresh CreateOS sandbox for each scan and clones the repository into it. Nothing from the project ever runs on your computer, and the sandbox is destroyed when the scan ends.

const sb = await client.createSandbox({ rootfs: "devbox:1", shape: "s-1vcpu-1gb" });
02Lock the network

Only the package registry gets through.

Once the code is inside, the sandbox's egress allowlist is narrowed to the npm registry. Installing dependencies still works. Anything else the project tries to reach is refused at the network level, and Tripwire records the attempt.

await sb.setEgress(["registry.npmjs.org:443"]);
03Write its own tools

The agent builds the analyzer it needs, and proves it works.

Raw traces are messy: many processes interleave, and lines are split mid-call. Rather than ship a fixed parser, the agent asks the model to write one, runs it inside the sandbox against a calibration trace with known activity, and checks the result.

If the parser misses something, the agent sends back the error together with the exact log lines it misread, and the model fixes its own code. Only a parser that passes is trusted with the real scan.

write→run in sandbox→check against known trace→fix
04Trace

Watch everything the install does.

A test file is planted in the home folder, a place no normal project needs to look. Then npm install runs under strace, which records every file opened and every connection attempted, along with the exact command responsible.

# every openat, connect and execve, across every child process
strace -f -e trace=openat,connect,execve npm install
05Fork

One install, many runs in parallel.

The installed sandbox is paused and forked. Each fork starts from the identical state and runs a different entry point, so npm start and npm test are checked side by side without reinstalling. A fork that misbehaves is paused, preserving its exact state as evidence.

await sb.pause();
const fork = await sb.fork({ egress: ["registry.npmjs.org:443"] });
06Report

A clear answer, with the evidence.

Every file outside the project and every blocked connection is matched to the command that caused it. You get a verdict, a plain-English explanation, and the details to check for yourself.

Looks clean

Only touched its own folder and normal system files. No outside connections.

Worth a closer look

Opened files outside its folder, or failed to install.

Behaves unexpectedly

Opened files in the home folder, or tried to reach a server it doesn't need.
